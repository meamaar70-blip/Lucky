## ۴) لبهٔ سه‌بعدی دکمه‌ها

دکمه‌ها مثل کلید فیزیکی‌اند: یک لبهٔ ثابت پایین + سایهٔ خنثی. هنگام فشردن، رویه پایین می‌رود.

```css
:is(.btn, .icon-btn, .theme-btn, .chip, .grade-btn, .opt, .week-day) {
  --key-depth: 3px;            /* دکمهٔ اصلی ۴px، دکمهٔ کوچک ۲px */
  box-shadow:
    inset 0 1px 0 var(--key-light),
    inset 0 -1px 0 var(--button-inset),
    0 var(--key-depth) 0 var(--key-edge),
    0 calc(var(--key-depth) + 3px) 8px var(--button-shadow);
}
```

اگر روزی سایه زیاد به نظر رسید، فقط `--key-depth` و توکن‌های `--button-*` را کم کنید؛ بقیهٔ چیدمان دست نمی‌خورد.

## ۵) موبایل

- زیر ۷۶۷px: `--btn-h` = `--tap` (۴۴)، عنوان صفحه ۱۷، فاصلهٔ محتوا ۱۶
- زیر ۴۷۹px: عنوان ۱۶.۵، متن ۱۴.۵، `--content-pad` ۱۴، `.row` عمودی می‌شود، ستون‌های دوگانه تک‌ستونی
- `body { overflow-x: clip }` + `min-inline-size: 0` روی فرزندان شبکه‌ها تا متن بلند سرریز نکند
- فضای امن ناچ با `env(safe-area-inset-*)`

## ۶) دسترس‌پذیری

- `:focus-visible` با `--ring` و `outline-offset: 3px`
- `aria-current="page"` روی آیتم فعال کشو
- لینک «پرش به محتوای اصلی» در ابتدای صفحه
- `role="timer" aria-live="polite"` روی شمارش معکوس آزمون
- سوئیچ‌ها `input[type=checkbox]` واقعی با هدف لمسی ۴۴px

## ۷) محدودیت‌های حفظ‌شده

- بدون گرادیان، بدون `backdrop-filter` (صفر مورد در `app.css`)، بدون تصویر/فونت بیرونی
- کلاس‌ها و idهای قلاب تست‌ها (`#view`، `.btn-primary`، `.badge`، `.nav-item[data-route]` …) دست‌نخورده
- CSS فشرده‌شده ≈ ۱۲ کیلوبایت (gzip) — زیر بودجهٔ ۴۰ کیلوبایت
